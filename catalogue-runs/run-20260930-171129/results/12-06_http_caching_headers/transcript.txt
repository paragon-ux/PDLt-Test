## Resource Types and Header Specifications

| Resource Type | Cache-Control | Vary | ETag | Surrogate-Control |
|---|---|---|---|---|
| **Static assets (JS, CSS, images) – deploy‑time only changes** | `public, max-age=31536000, immutable` | `*` (no vary needed for static) | Strong ETag based on file hash (e.g., `"<hex-hash>"`) | `max-age=31536000, stale-while-revalidate=86400` |
| **User profile data – updates at most once per day** | `private, max-age=86400, must-revalidate` | `Authorization, Cookie` (to differentiate users) | Weak ETag reflecting version stamp (e.g., `W/"profile-2023-09-30"`) | `no-store` (do not let CDN cache user‑specific content) |
| **Real‑time data (stock prices, live scores) – never stale** | `no-store, no-cache, max-age=0, must-revalidate` | `*` (generally none, but include any request‑header that influences representation) | Strong ETag based on current payload (e.g., `"<timestamp>"`) | `no-store` |
| **Public catalog data – identical for all users** | `public, max-age=3600, stale-while-revalidate=86400` | `*` (no vary needed) | Weak ETag based on content version (e.g., `W/"catalog-v5"`) | `max-age=3600, stale-while-revalidate=86400` |
| **Authenticated responses – vary per user** | `private, max-age=0, must-revalidate` | `Authorization, Cookie` | Strong ETag that includes user‑specific identifier (e.g., `"user-<id>-v2"`) | `no-store` |

### Rationale

1. **Static assets** – They are immutable after deployment, so a very long `max-age` with `immutable` tells browsers and CDNs they never need to revalidate. `public` allows any cache to store them. The surrogate (CDN) mirrors the same long TTL and uses `stale‑while‑revalidate` to serve a stale copy while fetching a new one after a deploy.

2. **User profile data** – Sensitive and user‑specific, therefore `private` prevents shared caches. A daily `max-age` matches the update frequency; `must-revalidate` forces caches to check after the day expires. `Vary` on authentication headers ensures separate cache entries per user. The CDN should not store it (`no-store`). A weak ETag is sufficient because exact byte‑by‑byte comparison is not needed; a version identifier suffices.

3. **Real‑time data** – Must never be stale, so `no-store` and `no-cache` guarantee every request reaches the origin. `max-age=0` and `must-revalidate` reinforce revalidation. No `Vary` needed unless request headers affect the payload. The CDN is instructed not to cache (`no-store`). A strong ETag reflects the exact current payload to allow conditional requests if a client already holds the latest value.

4. **Public catalog data** – Identical for all users, so `public` is appropriate. A moderate `max‑age` (1 hour) balances freshness with cache efficiency. `stale‑while‑revalidate` lets CDNs serve slightly stale data while refreshing in the background. A weak ETag based on a version number is enough for conditional requests.

5. **Authenticated responses** – Must be kept private and refreshed on every request (`max-age=0`). `Vary` on authentication headers ensures per‑user cache keys. `no-store` on the CDN prevents it from ever storing personalized content. A strong ETag includes the user identifier to allow conditional GETs when the same user repeats the request.

## Python Middleware

```python
from typing import Callable
from starlette.types import ASGIApp, Receive, Scope, Send
from starlette.responses import Response

# Mapping of resource identifiers to header specifications
HEADER_SPEC = {
    "static": {
        "Cache-Control": "public, max-age=31536000, immutable",
        "Vary": "*",
        "ETag": None,  # Should be set by static file server based on file hash
        "Surrogate-Control": "max-age=31536000, stale-while-revalidate=86400",
    },
    "profile": {
        "Cache-Control": "private, max-age=86400, must-revalidate",
        "Vary": "Authorization, Cookie",
        "ETag": None,  # e.g., W/"profile-2023-09-30"
        "Surrogate-Control": "no-store",
    },
    "realtime": {
        "Cache-Control": "no-store, no-cache, max-age=0, must-revalidate",
        "Vary": "*",
        "ETag": None,  # Strong ETag based on payload timestamp
        "Surrogate-Control": "no-store",
    },
    "catalog": {
        "Cache-Control": "public, max-age=3600, stale-while-revalidate=86400",
        "Vary": "*",
        "ETag": None,  # W/"catalog-v5"
        "Surrogate-Control": "max-age=3600, stale-while-revalidate=86400",
    },
    "auth": {
        "Cache-Control": "private, max-age=0, must-revalidate",
        "Vary": "Authorization, Cookie",
        "ETag": None,  # "user-123-v2"
        "Surrogate-Control": "no-store",
    },
}

def determine_resource_type(scope: Scope) -> str:
    """Inspect the request path or route name to decide which resource type it is.
    This is a placeholder mapping; adapt to your routing conventions.
    """
    path = scope.get("path", "")
    if path.startswith("/static"):
        return "static"
    if path.startswith("/profile"):
        return "profile"
    if path.startswith("/realtime"):
        return "realtime"
    if path.startswith("/catalog"):
        return "catalog"
    # Default to authenticated user‑specific endpoints
    return "auth"

class CacheControlMiddleware:
    def __init__(self, app: ASGIApp):
        self.app = app

    async def __call__(self, scope: Scope, receive: Receive, send: Send) -> None:
        resource_type = determine_resource_type(scope)
        spec = HEADER_SPEC.get(resource_type, {})

        async def send_wrapper(message):
            if message["type"] == "http.response.start":
                headers = message.setdefault("headers", [])
                for name, value in spec.items():
                    if value is None:
                        continue
                    # Starlette expects header names/values as bytes
                    headers.append((name.lower().encode(), value.encode()))
            await send(message)

        await self.app(scope, receive, send_wrapper)
```

The middleware inspects the request path (or any other metadata you expose) to classify the response, then injects the appropriate `Cache-Control`, `Vary`, `ETag` (if your view sets one), and `Surrogate-Control` headers before the response is sent.
