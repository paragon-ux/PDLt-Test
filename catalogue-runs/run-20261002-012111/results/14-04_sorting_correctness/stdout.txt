**Formal Correctness Proof of Merge Sort**

---

### Overview
We prove three properties of the merge‑sort algorithm on finite lists of elements from a totally ordered set:
1. **Termination** – the algorithm always terminates.
2. **Sortedness** – the output list is in non‑decreasing order.
3. **Permutation** – the output list contains exactly the same multiset of elements as the input list.

The proof proceeds by structural induction on the length of the input list.  The algorithm consists of two mutually recursive functions:
- `merge_sort(L)` – recursively splits the list and merges the sorted halves.
- `merge(A,B)` – merges two already sorted lists `A` and `B`.

We treat the correctness of `merge` as a separate inductive argument, which is then used in the main proof for `merge_sort`.

---

## 1. Termination

### Measure
Define the **size measure** `μ(L) = |L|`, the length of the list `L`.  For any finite list, `μ(L) ∈ ℕ` and ℕ is well‑founded under the usual < relation.

### Proof by Induction on `μ(L)`

**Base Case (`|L| = 0` or `|L| = 1`).**
- If `|L| = 0`, `merge_sort` returns `L` immediately – no recursive call is made.
- If `|L| = 1`, `merge_sort` also returns `L` immediately.
Both cases finish in a constant number of steps, so termination holds.

**Inductive Step.**
Assume that for all lists `X` with `|X| < n` the call `merge_sort(X)` terminates.  Consider a list `L` with `|L| = n ≥ 2`.
- `merge_sort` splits `L` into two sub‑lists `L₁` and `L₂` such that `|L₁|,|L₂| < n` (both are strictly smaller because the split is non‑trivial).
- By the inductive hypothesis, the recursive calls `merge_sort(L₁)` and `merge_sort(L₂)` terminate.
- After the two recursive calls return sorted sub‑lists, `merge` is invoked on them.  The `merge` routine is proven (see Section 2) to terminate for any finite inputs because each recursive step consumes one element from either argument, strictly decreasing the sum of their lengths.
Thus all recursive invocations made from `merge_sort(L)` terminate, and consequently `merge_sort(L)` itself terminates.

Since the measure `μ` strictly decreases on every recursive call and ℕ is well‑founded, termination follows for all finite input lists.

## 2. Correctness of the `merge` Subroutine

We prove two properties for `merge(A,B)` where `A` and `B` are sorted (non‑decreasing) lists.

### Lemma 2.1 (Sortedness of Merge)
*Statement*: `merge(A,B)` returns a list `C` that is sorted in non‑decreasing order.

*Proof by Structural Induction on `|A| + |B|`*:
- **Base Case (`|A| = 0` or `|B| = 0`).**
  If `A` is empty, `merge` returns `B`, which is sorted by assumption.  Symmetrically, if `B` is empty, the result is `A`.  Hence the result is sorted.
- **Inductive Step.**
  Suppose `|A| + |B| = k` with `k ≥ 1` and the lemma holds for all smaller sums.
  Let `a = head(A)` and `b = head(B)`.  The algorithm compares `a` and `b`:
  - If `a ≤ b`, the result is `a` cons `merge(tail(A), B)`.  By the inductive hypothesis, `merge(tail(A), B)` is sorted, and because `a ≤ b ≤` every element of `merge(tail(A), B)`, the whole list is sorted.
  - If `b < a`, symmetric reasoning yields a sorted list.
  Thus in all cases the returned list is sorted.
∎

### Lemma 2.2 (Permutation Preservation of Merge)
*Statement*: `merge(A,B)` returns a list `C` that is a permutation of the concatenation `A ++ B`.

*Proof by Induction on `|A| + |B|`*:
- **Base Case.** Same as Lemma 2.1: when one list is empty, the result is the other list, which trivially is a permutation of `A ++ B`.
- **Inductive Step.** Assume the lemma holds for smaller sums.  Consider the first comparison as above.
  - If `a ≤ b`, the result is `a :: merge(tail(A), B)`.  By the inductive hypothesis, `merge(tail(A), B)` is a permutation of `tail(A) ++ B`.  Adding `a` in front yields a permutation of `a :: tail(A) ++ B = A ++ B`.
  - The case `b < a` is symmetric.
Thus the output list contains exactly the elements of `A` and `B` with multiplicities preserved.
∎

## 3. Correctness of `merge_sort`

We now prove the three main properties for `merge_sort(L)`.

### Theorem 3.1 (Termination)
*Statement*: `merge_sort(L)` terminates for every finite list `L`.

*Proof*: Already given in Section 1.
∎

### Theorem 3.2 (Sortedness)
*Statement*: For any finite list `L`, the list `S = merge_sort(L)` is sorted in non‑decreasing order.

*Proof by Induction on `|L|`*:
- **Base Case (`|L| ≤ 1`).** The algorithm returns `L` unchanged, which is trivially sorted.
- **Inductive Step.** Assume the theorem holds for all lists of length `< n`.  Let `|L| = n ≥ 2`.
  The algorithm splits `L` into `L₁` and `L₂` with `|L₁|,|L₂| < n`.  By the inductive hypothesis, `merge_sort(L₁)` and `merge_sort(L₂)` produce sorted lists `S₁` and `S₂`.  The final result is `merge(S₁,S₂)`.  By Lemma 2.1, `merge(S₁,S₂)` is sorted.  Hence `merge_sort(L)` yields a sorted list.
∎

### Theorem 3.3 (Permutation)
*Statement*: For any finite list `L`, the list `S = merge_sort(L)` is a permutation of `L`.

*Proof by Induction on `|L|`*:
- **Base Case (`|L| ≤ 1`).** `merge_sort` returns `L` itself, which is trivially a permutation.
- **Inductive Step.** As before, split `L` into `L₁` and `L₂`.  By the inductive hypothesis, `merge_sort(L₁)` is a permutation of `L₁` and `merge_sort(L₂)` is a permutation of `L₂`.  Their concatenation therefore is a permutation of `L₁ ++ L₂ = L`.  Applying `merge` to these two sorted lists yields, by Lemma 2.2, a permutation of `L₁ ++ L₂`.  Hence the final result `merge_sort(L)` is a permutation of the original list `L`.
∎

3. Produces an output list that is a permutation of the input list.
